# Deploying paid memberships

The frontend is Next.js 16; the Go API and isolated Vercel Sandbox executor are separate services. `vercel.json` routes public traffic to Next.js and binds `GO_API_URL` to the Go service. Keep the API service private: execution completion must only be submitted by the trusted Next.js executor.

## Account and database setup

1. Apply every migration in `supabase/migrations` in order. The tracked migration runner (`npm run db:migrate`) uses `POSTGRES_URL`, checksums, and one transaction. Coordinate the new frontend/API release with migration 003: it immediately removes unpaid database access. No production migration is implied by passing the local test suite.
2. Set `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, and the **server-only** `SUPABASE_SERVICE_ROLE_KEY` on Next.js. Go uses `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY`, forwarding each user's token.
3. Set the Supabase Site URL to the canonical application origin. Allow `/auth/callback` and `/auth/callback?next=/reset-password` at that origin. Add localhost only for development.
4. Enable email auth, confirmation, production SMTP, rate limits, and abuse controls. Disable anonymous sign-ins; the application rejects anonymous users even if that provider is accidentally enabled.
5. Configure each desired OAuth provider in Supabase with its own client ID/secret and the **Supabase callback URL** displayed in its dashboard. The UI discovers enabled providers rather than offering broken buttons. Supported adapters: Google, GitHub, Apple, Microsoft, Discord, GitLab, Bitbucket, LinkedIn OIDC, Slack OIDC, Notion, Figma, Twitch, Spotify, Facebook, Zoom, Kakao, X, legacy Twitter, Keycloak, WorkOS, and Fly.io. Provider registrations and secrets are external setup, not generated by this repository.
6. For SMS codes, enable Phone and configure a supported SMS service. For SAML SSO, configure organization domains in Supabase and set `NEXT_PUBLIC_ENABLE_SSO=true`. Social sign-in can create an account; it never grants a paid entitlement.

## Billing

The configured plans are Focus at **₹499/month** and Momentum at **₹3,999/year** (INR). Both include every feature and **500 runs/calendar month**, capped at **50/day** and **5/minute**, reset in UTC. No free tier or trial. Annual billing does not grant 6,000 runs upfront. Invalid code and reserved runs that encounter execution failures count; saving notes/drafts does not consume runs.

1. Use a Stripe account capable of accepting the intended payments. Create one product and two active, fixed recurring INR prices: 49900 minor units/month and 399900/year. Set `STRIPE_MONTHLY_PRICE_ID` and `STRIPE_ANNUAL_PRICE_ID`. Checkout validates the currency, amount, interval, and usage model against the displayed plans. Do not configure trials or discounts that make invoices free. If tax collection is required, configure and test the appropriate Stripe tax behavior before launch; this checkout does not enable automatic tax collection.
2. Set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and `APP_URL` on Next.js only. Test and live keys/price IDs/webhooks must belong to the same mode.
3. Register `https://YOUR_APP/api/billing/webhook` with the Stripe API version matching the installed SDK. Subscribe to `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`, `invoice.payment_failed`, `invoice.payment_action_required`, `invoice.voided`, and `invoice.marked_uncollectible`.
4. Enable the hosted Customer Portal for payment methods, invoice downloads, and cancellation **at period end**. Disable trials, subscription pausing, and switching to unrecognized prices. Cancellation at period end keeps access until the paid date. Immediate cancellation and delinquent states lock the lab. If you issue a refund, cancel the subscription as part of that workflow; standalone refund events do not cancel membership automatically.
5. A signed webhook re-fetches the current subscription, verifies its customer mapping and recognized price, and stores the paid period. Access requires `active` plus an unexpired positive-value paid invoice. The success URL never grants access. Older events and old-subscription cancellation cannot overwrite a newer entitlement. Non-2xx webhook responses must be retried and monitored.
6. Checkout locks are stored in Postgres; open sessions are reused, interval changes expire the previous checkout, and active/incomplete subscriptions route to portal management instead of duplicate purchases. Test delayed payment confirmation, failed renewal, retry, cancellation, duplicate delivery, and resubscription in Stripe test mode before enabling live payments.

## Execution and usage

Run `npm run sandbox:prepare` with Vercel credentials to build a trusted runtime snapshot containing Go, Python, and Node. Supply its `SANDBOX_SNAPSHOT_ID` to Next.js. Learner runs use ephemeral microVMs with denied outbound networking, bounded execution, and no application credentials. The Next.js run handler allows up to 120 seconds; ensure hosting limits support this. Do not log code, notes, bearer tokens, or payment secrets.

Usage events record client-reported learning page views, authenticated API attempts/outcomes/duration, run reservations, draft/note writes, and sign-ins. Database triggers record saves even through direct database requests. RLS restricts member usage to its owner. `/billing` remains accessible without payment for billing and usage inspection; learning pages, API operations, the Go catalog, and learning database rows require payment. Lesson JSON is server-only and delivered through the authenticated layout, not a public JavaScript bundle.

Set `ADMIN_USER_IDS` to designated Supabase user UUIDs to enable `/admin` reporting across users. Administrators do not receive free lab access. The service role is the only role allowed to call the cross-user reporting function. Do not expose this credential or assign administrators from client-editable user metadata. Activity is retained with the account and cascades on account deletion; choose a retention policy before scaling.

## Verification and release

Run `npm run check`, `go test -race ./...`, and `npm run build`. Membership tests run actual Postgres SQL in an isolated in-memory PGlite instance; they do not touch the connected database. Verify with two real test accounts that paid access, row privacy, saving, reload, all three execution languages, provider callbacks, email confirmation/recovery, phone codes, and SSO work against configured services. Monitor webhook failures, executor failures, and usage event completion failures.

References: [Supabase social providers](https://supabase.com/docs/guides/auth/social-sign-in), [phone authentication](https://supabase.com/docs/guides/auth/phone-login), [Stripe subscription webhooks](https://docs.stripe.com/billing/subscriptions/webhooks).
